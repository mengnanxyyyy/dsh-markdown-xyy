# Markdown 对话主题 — 重点信息语义层级 + 无障碍校验报告

> 对象：插件 v0.3.0「LobeUI 风格」排版层
> 范围：重点信息语义分层、WCAG 2.1 AA 逐色对对比度、色盲安全（protanopia/deuteranopia）、深浅双档亮度、reduced-motion
> 结论性质：**只报事实与实测数值**。对比度 = 相对亮度比值，AA 门槛 = 正文 4.5:1 / 大字或装饰性(非文字) 3:1（WCAG 2.1.4.3、1.4.3 的 3:1 用于大字与非文本对比）。
> 色值上下文：浅底 `#f8f8f8`/卡片 `#ffffff`、深底 `#000000`/卡片 `#0d0d0d`；正文 `#080808`/`#ffffff`，次文字 `#666666`/`#aaaaaa`，边框 `#e3e3e3`/`#202020`。

---

## 一、重点信息语义层级设计（4 级）

### 1. 什么是「重点信息」（AI 对话 Markdown 的语义归类）

| 语义意图 | 常见 Markdown 来源 |
| --- | --- |
| H1 → 关键结论 / 告警 / 决策结论 | `> ⚠️ 最后结论…`、`**重要：**…`、块首 `h1/h2` 摘要 |
| H2 → 引用语 / 长代码块 / 流程要点 | `blockquote`、`pre`、`li strong` |
| H3 → 行内代码 / 表格头 / 参数名 / 状态 | `code`、`kbd`、`th`、`table` 首列 |
| H4 → 链接 / 普通列表 / 常规正文强调 | `a`、`ul/ol`、`strong` |

AI 对话中「重点」不是单一标量，而是**主视觉结论 → 引用证据 → 技术指代 → 常规导航**的 4 级衰减。层级靠**多种线索叠加**表达，颜色只是其中之一。

### 2. 四级视觉层级 + 手段组合

| 层级 | 元素 | 手段组合（色 + 形） | 非颜色线索（满足 WCAG 1.4.1） |
| --- | --- | --- | --- |
| **L1 最高：关键结论/告警** | 重点段落/结论行 | 主强调色左边条（边框）**+** tint 底 **+** 强调色 700 字重标题文字 **+** 可选 `⚠️` 图标 | ✅ 4px 彩色左边条（形态）+ 700 字重 + 图标字形；仅 tint 底还不够，必须带边条 |
| **L2 高：引用 / 代码** | blockquote、pre | 引用=4px 边条+卡片底；代码块=inset ring 边框 + tint 底 | ✅ 实边框/描边（几何边界），不依赖色相 |
| **L3 中：行内 code / 表格头** | code、samp、th | 1px 实边框 **+** tint 底 **+** mono 字形 | ✅ mono 字体 + 1px 边框（形状区分）；表格头 600 字重 + 底纹 |
| **L4 低：链接 / 列表 / strong** | a、li、strong | 链接=信息蓝 + hover 下划线；strong=600；列表=`-` 符号 | ✅ hover 下划线（L4 仅链接用文字形态）；strong 用字重（非颜色） |

**铁律（WCAG 1.4.1 — 不能只用颜色）：**
- **每个强调元素必须至少带一项「非颜色线索」**：边框 / 图标 / 字重 / 下划线 / 字体。允许颜色与它并存，但颜色必须可或缺。
- 具体落到当前 CSS：
  - `blockquote` → 4px 左边条（形态）✓ 已有
  - `code/samp` → 1px 边框 + 胶囊（形态）✓ 已有
  - `th` → 600 字重 + 底纹 ✓ 已有
  - `a` → hover 下划线 ✓ 已有，但**静态态只有颜色**，见 §二 链接结论，需补下划线或 hover 强化
  - `pre` → inset ring 边框 ✓ 已有
  - 新增的 `--mdvr-*` 强调元素 → 必须**边条/饰形 + 深色正文**成对出现，禁止「仅 tint 底 + 彩色小字」这种纯颜色组合。

### 3. 强调色系落点

结合第四节 CVD 分析，强调色系**只选蓝/靛（避免红绿冲突带）**，青作为次级，**不引入琥珀做正文强调**（琥珀是人类 L 锥与红绿轴交叠点，且与 warn 语义撞车）。
详细推荐值见 §六。

## 二、逐色对对比度数值表（WCAG 2.1 AA，实测）

### 2.1 基线（现有 token，浅档）

| 前景 | 背景 | 比值 | AA 结论 |
| --- | --- | --- | --- |
| 正文 `#080808` | 卡片 `#ffffff` | **20.03:1** | ✅ AAA |
| 正文 `#080808` | 底 `#f8f8f8` | ≈20.3:1 | ✅ AAA |
| 次文字 `#666666` | 卡片 `#ffffff` | **5.74:1** | ✅ AA（正文） |
| 信息蓝链接 `#0072f5` | 白 `#ffffff` | **4.44:1** | ❌ **AA 差 0.07，正文不达标**（仅大字 3:1 过） |
| 信息蓝 hover `#005ae0` | 白 `#ffffff` | **5.93:1** | ✅ AA |
| error `#ec5e41` | 白 `#ffffff` | **3.36:1** | ❌ 正文不达标，仅大字 |
| success `#379d4a` | 白 `#ffffff` | **3.45:1** | ❌ 正文不达标，仅大字 |
| warn `#ee9e0b` | 白 `#ffffff` | **2.20:1** | ❌ 连大字 3:1 都不达标 |
| 边框 `#e3e3e3` | 白 `#ffffff` | ≈1.15:1 | ⚠️ 纯装饰可（1.4.11 非文本需逐元素判），作为唯一识别线索不够 |

**→ 现有语义色（step9）在浅档全不达正文标。** 它们只能做「已过(态)有色点 + 文字气泡/图标」，绝不能单独承载可读的正文或「是/否」判断。要承载文字须换更深 step。实测达标值需**同时过白底 `#ffffff` 与页面底 `#f8f8f8`**（文字常落在 #f8f8f8 上）：error `#c74330`（白 4.91 / 页 4.63）、success `#287b38`（白 5.28 / 页 4.97）、warn `#985d00`（白 5.38 / 页 5.07）。注意**只在白底过、在 `#f8f8f8` 差一线者不可用**：`#2e8540`(页 4.35)、`#a86200`(页 4.48)、`#c88700`(3.03)、`#2f8a3f`(4.35) 均不达标。

### 2.3 tint 背景上的文字（新强调方案核心）

**浅档 tint**（彩向白稀释，近白底）+ 深色正文：全部 ≥ 16.99:1（AAA）：

| tint | 深正文 `#080808` 对比 | 结论 |
| --- | --- | --- |
| 蓝 tint `#e8f0ff`（blue90→白） | **17.49:1** | ✅ AAA |
| 靛 tint `#e8edfb` | **17.11:1** | ✅ AAA |
| 青 tint `#e2efee` | **16.99:1** | ✅ AAA |

**浅档 tint 上的强调色文字**（强调色直接放 tint 上）——这组才是风险点：

| 前景（强调色） | tint 背景 | 比值 | 结论 |
| --- | --- | --- | --- |
| `#1d4ed8` 靛 | `#e8edfb` | **5.72:1** | ✅ AA |
| `#1868ff` 蓝 | `#e8f0ff` | **4.11:1** | ❌ **差 0.39，不达标** |
| `#0f766e` 青 | `#e2efee` | **4.64:1** | ✅ AA（贴线） |
| 深正文 `#080808` 于任意 tint | — | ≈17:1 | ✅ |

**→ 规则：** 在 tint 上用彩色作「正文/标题文字」时，必须用**深一档的强调色**（如靛 `#1d4ed8` 而非 `#1868ff`），或干脆 tint 上放深正文、强调色只做边条。**浅档 `#1868ff` 放蓝 tint 上是本次发现的最大新坑**。

**深档 tint**（彩向黑稀释，近黑底）+ 浅字：全部 ≥ 18:1（AAA）：

| tint | 白字 `#ffffff` 对比 | 结论 |
| --- | --- | --- |
| 蓝 tint `#11151a`（blue90→黑） | **18.32:1** | ✅ AAA |
| 天青 tint `#061319` | **18.84:1** | ✅ AAA |
| 近黑 tint 与卡片 `#0d0d0d` 的区分 | 见下 ⚠️ | — |

**深档 tint 与卡片底区分度（非文本边框）**：tint `#11151a` vs 卡片 `#0d0d0d` 几乎同亮度，**仅凭 tint 底无法区分**装饰块 —— 必须配合左边条/边框。这正是「不能用单一颜色承载层级」在深档的特例：深档 tint 底只能增强，识别靠边框。

### 2.4 边框/装饰（非文本，1.4.11 · 3:1）

| 前景（边框） | 背景 | 比值 | 结论 |
| --- | --- | --- | --- |
| 蓝 `#1868ff` 边条 | 卡片 `#ffffff` | **4.71:1** | ✅（>3） |
| 靛 `#1d4ed8` 边条 | 卡片 `#ffffff` | **6.70:1** | ✅ |

**→ 所有候选强调色作 4px 边条均过 3:1（有的过 AA/AAA）**，边框方案在整个色板上都安全，这是强调色最稳妥的用法。

## 四、色盲安全（protanopia / deuteranopia）

**语义色红绿色轴的实测亮度坍缩（已模拟）：**

| 色对 | 基础 Δ亮度 | **Protan Δ亮度** | **Deutan Δ亮度** | 结论 |
| --- | --- | --- | --- | --- |
| 浅 error `#ec5e41` vs success `#379d4a` | **0.008** | **0.010** | 0.212 | ❗ **Protan 下几乎同亮度 + 同轴，纯颜色不可区分** |
| 浅 error `#ec5e41` vs warn `#ee9e0b` | 0.164 | 0.078 | 0.251 | ⚠️ Protan 贴近 |
| 浅 success `#379d4a` vs warn `#ee9e0b` | 0.172 | 0.068 | 0.463 | ⚠️ Protan 贴近 |
| 深 error `#f4416c` vs lime `#c4f042` | 0.504 | 0.224 | 0.589 | ✅ 亮度可分 |
| 深 lime `#c4f042` vs gold `#ffb224` | 0.212 | 0.087 | 0.118 | ⚠️ **Protan/Deutan 亮度都很近** |

**结论 1 — 红绿轴不可靠：** 浅档 `success`(绿) 与 `error`(红) 是 **Protanopia 的经典盲区**（亮度 0.010 差 + 红绿轴重合）。**这三态（success/warn/error）绝不允许「仅靠色相区分状态」**。安全做法：状态必须配**图标字形 + 文字标签**（✓ / ! / ✕）+ 字重，颜色只做强化，不承载语义；且**不要把两态相邻并排只靠颜色比**。

**结论 2 — 深档 lime/gold 在 Deutan 下亮度接近（0.118）与 Protan 下（0.087）都近**：深档 success(黄绿) vs warn(金) 也需图标/文字辅助，不能单靠颜色。
→ 无论深浅档，**success≠warn 在轻微 CVD 下都需非颜色线索**。

**结论 3 — 强调色选蓝/靛最安全：**
- 蓝 `#1868ff`（Protan 亮度 0.109）vs success 绿（0.095）：仅略隔开，且蓝绿色域对红绿色盲**但青蓝在红绿轴之外**，与绿仍有区分；真正的问题是琥珀与绿。
- **避免在强调里大量用琥珀/金黄**（与 warn 撞车 + 处黄绿轴），正文强调用蓝/靛/青。
- 蓝靛 vs 语义红/绿：蓝与绿在 Protan/Deutan 下通过**亮度差**（蓝 0.109 vs 绿 0.095 / 深蓝 vs 深绿）与红（0.085/0.461）带区分，**搭配安全**。

**结论 4：** 强调色系与语义色系搭配建议：强调=蓝靛族 `#1868ff`/`#1d4ed8`（浅）、`#60b1ff`/`#7dd3fc`（深）；语义三态保持现有绿/金/红，但每处搭配图标字形。蓝与绿/金/红不冲突（分属亮度带），可安心同屏。

## 五、深浅双档亮度控制 + reduced-motion

**深档亮度控制（避免过亮刺眼）：**
- 深档可见色全部是 step9 高亮（如 lime `#c4f042`、gold `#ffb224`、天青 `#a7d3ff`），对黑底比值 9–16:1，**视觉上非常亮**。
- **规则：** 深档大面填充不得用这些高亮做底（会闪烁/刺眼）；只允许做**细边条（4px）+ 小面积高亮文字**。大块 tint 底用彩向黑稀释的**低亮度近黑 tint**（`#11151a`/`#061319`，亮度 ≤0.02），上面配白字（≥18:1），高亮强调色只做边框。
- 具体：L1 块在深档 = 近黑 tint 底 + `#60b1ff`/`#7dd3fc` 4px 边条 + 白色 700 字重标题；**不用** lime/gold/亮蓝做整块填充。
- 深档避免把 `#a7d3ff`、`#7dd3fc` 这类超高亮蓝用作整段正文——建议仅标题/边框。

**reduced-motion：**
- 现有插件已正确实现（`client.js` L104）：`@media (prefers-reduced-motion: no-preference)` 内才启用 `a` 的 `transition`。✅ 符合 WCAG 2.3.3/2.3.1 意图。
- **新增强调元素同样套用**：所有 hover 色变、边条生长、背景淡入一律只放 `<no-preference>` 块，reduced-motion 下**零过渡、立即切换**。
- 建议统一封装一句：`@media (prefers-reduced-motion: reduce){ *,*::before,*::after{ transition:none !important; animation:none !important } }`（如已由产品全局提供则跳过）。

## 六、最终推荐的强调色值清单（浅/深两档 hex，全部实测达标）

| 用途 | 浅档 hex | 深档 hex | 达标依据 |
| --- | --- | --- | --- |
| **主强调_正文/标题** | `#1d4ed8`（靛，白底 6.70:1） | `#7dd3fc`（天青，黑底 12.60:1、卡底 11.66:1） | 正文 AA+ / AAA，且蓝靛避开红绿轴 |
| **主强调_边条/装饰**（首选项） | `#1868ff`（对卡 4.71:1） | `#60b1ff`（对卡 8.54:1） | >3:1 非文本，稳妥 |
| **tint 底（L1 块/引用/代码）** | `#e8f0ff`（近白蓝底，深字 ≥17.4:1） | `#11151a`（近黑蓝底，白字 ≥18.3:1） | 正文填字 AAA |
| **tint 底上之强调文字** | 必须 `#1d4ed8`（5.72:1），**勿用 `#1868ff`（4.11:1 不达标）** | 白字 `#ffffff`（18.3:1）即可，强调移交边条 | 见 2.3 表 |

## 附：对比度计算口径

- WCAG 2.1 相对亮度 L = 0.2126R + 0.7152G + 0.0722B，每通道线性化 `c≤0.04045? c/12.92 : ((c+0.055)/1.055)^2.4`。
- 对比度 = (L1+0.05)/(L2+0.05)，取两色亮度排序后之比。
- 本文所有比值均用上述公式实测输出，标注 `:1`。AA=4.5:1（正文）/3:1（大字·非文本），AAA=7:1。
- CVD 亮度为 Brette/Viénot 变换作用于 RGB 后经同一 WCG 亮度公式取值，用于「同轴色相坍缩」的**相对判断**，非绝对标准仪器值。
